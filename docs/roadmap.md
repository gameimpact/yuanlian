# 阶段路线图

本文件描述工作顺序与进入/退出条件，不是工期承诺。任何阶段完成都必须有实际构建与测试证据；未实测项不能标完成。需求状态以 [requirements-traceability.md](requirements-traceability.md) 为准。

## M0 — Windows 引擎垂直切片（2026-10-18 完成）

范围：真实屏幕采集、变化图块 JPEG、静止精修、TLS + 指纹固定、SendInput、原生测试查看器、需求/协议/ADR 文档。

退出条件（已满足）：

- `cargo check --workspace` 通过且无警告；9 项单元测试通过。
- `--capture-test` 抓到真实桌面（3200×2000），保存截图成功。
- `--test-input` 鼠标注入误差 0 px。
- 查看器经 TLS 连接 Host，真实画面显示；本地窗口中心映射到远端 (1600,1000)，连续采样无漂移。
- 错误指纹拒绝；Host 未授权时强制输入仍被拒绝并回 `input_denied`。

M0 明确不包含：Flutter 产品 UI、账号/配对、服务端、文件、Linux/Android、质量模式、中继。

## M1 — Windows 产品闭环

目标：把 M0 引擎嵌入真正的产品 UI，并完成账号/设备/授权的最小闭环。

1. **Flutter + Rust 桥**
   - `flutter_rust_bridge` 或稳定 C ABI，定义能力查询、连接、授权、输入、模式、文件、诊断接口。
   - 画面使用 native texture/GPU 路径；禁止逐帧复制为 Dart 大对象。先在 Windows 上测量拷贝开销与呈现延迟。
2. **Flutter 页面**：C01 首启、C02 服务器配置、C03 登录、C04 首页、C05 设备、C06 详情、C07 进度、C08 入站授权、C09 工作区、C10 模式设置、C13 设置、C16 本机 Host 管理。先从真实可用的子集开始，每个按钮接真实逻辑。
3. **Host 产品化**：托盘、本机允许被控开关、权限/目录设置、连接提示条、一键断开、Windows 服务安装与正常提权流程。
4. **最小服务端**：Rust API、设备身份、账号/MFA、会话票据、SQLite 单机演示（声明并发限制）与 PostgreSQL 方案；服务端不得能绕过 Host 本地拒绝。
5. **设备配对**：首次信任显示可核对指纹；配对与账号授权分层；撤销后阻断新会话。
6. **文件传输基础**：双栏、上传/下载、块校验、暂停/续传、冲突策略；先 Windows↔Windows。
7. **安装包**：MSIX/EXE 安装器或便携版，服务组件与卸载残留验证。

退出条件：Windows 到 Windows 的查看、控制、授权、模式（至少图块引擎）、文件基本任务可真实操作；每个 UI 状态有真实来源；核心流程有实机截图与日志证据。

## M2 — 跨平台与采集/输入完善

- Windows：DXGI Desktop Duplication 或 Windows Graphics Capture 采集；硬件 H.264/HEVC 编解码；多显示器、混合 DPI、旋转、热插拔；中文 IME 文本提交；相对鼠标/拖拽捕获；手柄。
- Linux：X11 与 Wayland（ScreenCast/RemoteDesktop Portal + PipeWire）分别实现与实测；systemd 用户服务/系统服务边界。
- Android：Flutter 主控（触控板/直接触控、文件 SAF、前台传输）；有人值守 Host（MediaProjection 每次同意、无障碍/输入按授权、前台服务、锁屏限制）。不承诺 Android 质量模式 Host。
- 音频/剪贴板通道与独立队列。
- 退出条件：18 个桌面模式组合 + 6 个 Android Host 组合有真实矩阵记录；未支持项明确 UI 原因。

## M3 — 质量模式、中继与策略

- 质量模式：锁定 Sunshine 与 moonlight-common-c 版本/子模块，完成产品内嵌显示、配对、撤销、硬件能力协商、统计；验证中继承载全部必要通道。
- 非视频兼顾模式补强：无损文字/线条区域、滚动复用、块版本/缓存 TTL、提交/呈现策略、带宽软/硬限制。
- 流畅模式：1 Mbps 总会话预算、拥塞控制、背压、有界队列、文件/音频分账、计费网络提示。
- 传输：QUIC 可靠流/数据报、TLS 回退、NAT 穿透、授权中继、短时票据与 2 秒内撤权。
- 策略与配置：schema、版本、下发、端点确认、回滚；服务端 GUI 的 S01–S10。
- 性能与安全专项：15.3/15.4 全部指标、模糊测试、撤权/重放/路径逃逸测试。

## M4 — 交付与验收

- 全量需求矩阵、安装/升级/卸载、备份恢复、证书轮换、审计、告警。
- 用户/管理员手册、许可证与第三方声明、可复现构建、测试证据包。
- 2 小时稳定性、文件 4 GiB/万文件/断网续传、Android/Linux 实机。

## 关键风险与应对

| 风险 | 应对 |
|---|---|
| Flutter 纹理/FFI 桥性能 | M1 第一件事做 spike，测实际拷贝/呈现开销；失败则用平台视图/独立原生子窗口作为过渡，但不冒充最终形态 |
| Moonlight 嵌入与中继多通道 | 阶段 0 式技术验证先行：产品窗口内出画、撤销真停输入、中继全部通道；不成功则明确阻塞与替代 |
| Wayland 限制 | Portal 能力检测 + 本机确认；无人值守/登录界面明确“不支持” |
| Android 权限/后台限制 | 每次 MediaProjection 同意、前台服务、SAF；不绕过系统安全界面 |
| 许可证 | AGPL-3.0-or-later + 上游声明/源码；闭源发行单独评估 |
| 单会话/单显示器等 M0 限制 | M1 起改为多会话路由与独立通道；在 UI 明确能力状态 |
