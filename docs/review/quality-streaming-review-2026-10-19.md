## 剩余缺口与修改意见

### P1：正式质量模式前必须补齐

1. **Host 侧授权/撤权桥接**。Moonlight 仍绕开 `yl-host` 的票据、本机权限交集和中心撤权。仅在启动前查一次登录、或本地 kill Moonlight，都不能解决已配对凭据旁路连接。实现 Host broker/adapter：验票、nonce/设备/用途绑定、本机授权、权限、租约与真实终止；不能施加只读/输入限制的组合必须明确拒绝或保持外部预览。验收包括撤销后已建立会话停止，以及已有上游配对凭据不能重连旁路。
2. **主程序异常退出清理**。正常返回已覆盖；远联崩溃或被强制结束时 Flutter dispose 不保证执行。补 Windows Job Object kill-on-close 或监督器，并做崩溃/启动竞态/子进程不响应故障测试。它只能补客户端生命周期，不能替代 Host 中心撤权。
3. **真实会话/安全状态回执**。目前只有进程状态，没有首帧、实际 codec/硬解、实际权限与加密策略事件。增加可信的上游能力与会话桥，配置/验证各必要通道的安全策略；中继只能转发端点密文。不要猜测进程存活或任意解析原始日志来显示“已连接/E2EE”。

### P2：产品与跨平台

4. **配对和应用列表尚在外部 GUI**。按钮只是打开上游，不代表远联完成配对/查询。后续适配应有取消、超时、数据上限，区分未配对/离线/应用不存在/编解码失败；PIN 不进日志/命令历史。
5. **运行时组件可信性**。固定 zip 哈希是打包证据，定位器 `existsSync` 不是运行时完整性验证。补整套组件清单/版本/依赖能力检查；失败不能显示“已验证”，提供官方包恢复步骤。
6. **能力协商/实际参数**。可选 4K、90/120、AV1、硬解不代表目标支持。探测 Host/Viewer 后才启用相应项，显示请求/实际/降级原因，不静默改为图块档。
7. **Flutter 内嵌与三档切换**。仍缺 Moonlight 核心→原生 Surface/Texture、焦点/释放、首帧、代际、切换与回滚；远联协议 v2 的 `mode=tiles` 未因此改变。
8. **Android/Linux 质量主控**。现在只有 Windows 外部 exe。Android 按用户要求以 MuMu 主测、自行准备环境、多 Android 版本分列，真机触控/硬解/省电另验；Linux 需真实 X11/Wayland 主控实现。
9. **质量专项验收**。缺本轮两物理机、1080p60 至少 10 分钟、1440p/4K、音频/HDR/手柄、输入延迟 p95、两小时、弱网/UDP 阻断/跨 NAT/中继证据。CLI 解析通过不证明这些能力已经运行通过。

### P2：安装和分发

10. **打包目录安全**。`packaging/quality/build-quality-preview.ps1` 构建前递归清理计算出的 `$stage`，未先核验解析后的绝对目标边界及是否为用户运行目录；配对状态检查位于清理之后。建议采用唯一临时 staging、输出路径边界检查、拒绝覆盖含运行状态的目录，校验成功再发布新包。本轮仅静态审查，未运行该脚本或删除该目录。
11. **源码与构建材料**。已有上游 URL、commit、许可证和 source offer，但本轮未复现完整源码/子模块/依赖/构建材料。准备可校验的对应源码包和构建记录，保留上游声明；不以外部进程或非商用标签替代分发要求。
12. **产物对齐**。本轮只重建 Flutter Windows release；未替换 DS 的安装器/质量 zip、更新 GitHub Release 或签名。后续发布时统一源码、客户端、组件、哈希和对应材料，不能把旧包性能/哈希当作新构建证据。
